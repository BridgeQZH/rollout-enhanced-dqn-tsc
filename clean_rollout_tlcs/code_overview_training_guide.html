clean_rollout_tlcs 代码核心逻辑与训练指南

这是对当前目录下小型代码库的只读梳理。代码实现的是一个基于 SUMO/TraCI 的交通信号控制训练框架： 用 DQN 学习价值函数，并让该价值函数作为 rollout 控制器的尾部价值。

一眼看懂

入口训练脚本

train.py 是唯一训练入口。它按 seed 循环生成交通流、启动 SUMO、采样经验、训练 DQN，并保存模型与曲线。

状态12 维车道组计数

env.get_state() 返回 12 维向量，表示路口四个进口方向的右/直/左车道组在停止线附近的车辆数。

动作4 个绿灯相位

动作 0-3 分别对应南北直行/右转、南北左转、东西直行/右转、东西左转。相位变化会插入黄灯。

奖励负排队成本

stage_cost 计算 g(x,u,u_prev) <= 0，训练奖励就是 reward = g，没有二次取负。

文件职责

文件核心职责

核心训练流程

  1. train.py 读取 settings/training_settings.yaml，构造 Model、Environment、DQNAgent 和 TransitionModel。
  2. 对每个训练 seed 建立独立目录，例如 model/seed_0。
  3. 每个 episode 先线性衰减探索率：epsilon = max(0, 1 - episode / total_episodes)。
  4. 用 training_seed * 10000 + episode 生成当前 episode 的交通流 route 文件。
  5. 启动 SUMO，循环直到 max_steps：读取 12 维状态、用 DQN 选动作、计算奖励 g、执行黄灯/绿灯、读取下一状态并存入 replay memory。
  6. episode 结束后执行 training_epochs 次经验回放训练，默认是 800 次。
  7. 保存模型、配置快照、训练曲线数据/图片和 run_manifest.json。

奖励与折扣

奖励函数在 Environment.stage_cost 中。它统计当前动作没有服务到的车道组队列，并在动作持续窗口内做折扣求和。 如果相位发生切换，动作窗口为 green_duration + yellow_duration；否则只有绿灯时间。 

Delta = green + yellow * 1[action != prev_action]
c = sum(unserved_queue)                     # linear 模式
g = -c * (1 - gamma^Delta) / (1 - gamma) - switch_penalty

DQN 的 bootstrap 也使用同一个有效时间窗口：目标值为 reward + gamma^Delta * max_a Q(next_state, a)。这让 DQN 学到的尾部价值 H=max Q 和 rollout 的阶段成本处在同一尺度上。

Rollout 逻辑

虽然训练脚本训练的是 DQN，但 agent.py 还实现了评估时可用的多种控制策略：

  • dqn：epsilon-greedy 或贪心 Q 网络动作。
  • fixed_time：固定顺序循环 0 → 1 → 2 → 3。
  • greedy：只看当前阶段成本 g，选成本最高也就是最不差的动作。
  • rollout_1s：对每个候选动作计算 g + beta * gamma^Delta * H(f(x,u))。
  • rollout_ms：先枚举第一步动作，后续用 greedy base policy 前推多步，最后接 DQN 尾部价值。

转移模型 f 在 transition.py 中，是一个 point-queue / store-and-forward 近似： 当前队列 + 到达车辆 - 绿灯放行车辆，并把结果裁剪到车道容量内。到达率来自环境中的上游虚拟检测器和旅行时间滞后修正。

运行训练前的条件

当前代码引用 intersection/sumo_config.sumocfg 和 intersection/episode_routes.rou.xml。 在我读到的当前目录文件列表中，没有看到 intersection/ 资产目录。因此，直接训练大概率会因为 SUMO 配置文件缺失而失败。
  • 需要安装 Python 依赖：numpy、torch、pydantic、PyYAML、traci、sumolib，以及可选的 matplotlib 用于保存曲线图。
  • 需要本机安装 SUMO，并确保 sumo 或 sumo-gui 能被 sumolib.checkBinary 找到。通常还需要设置 SUMO_HOME。
  • 需要把 SUMO 网络资产放到训练工作目录下的 intersection/，并保证 settings/training_settings.yaml 中的 sumocfg_file 指向真实存在的 .sumocfg。

推荐训练命令

这个包的导入使用相对导入，例如 from .env import Environment。因此最好从包目录的父目录运行模块。 当前目录是 D:\rl_cc\clean_rollout_tlcs，父目录应是 D:\rl_cc。 

cd D:\rl_cc
python -m clean_rollout_tlcs.train --settings clean_rollout_tlcs/settings/training_settings.yaml --out clean_rollout_tlcs/model --seeds 0,1,2

如果从当前包目录内部运行，直接 python train.py 通常会遇到相对导入错误；除非你把它作为包安装，或者调整 PYTHONPATH。

训练产物

每个 seed 会生成一个独立目录，例如 model/seed_0/，里面包括：

  • trained_model.pt：PyTorch state_dict checkpoint，包含架构元数据。
  • training_settings.yaml：本次训练配置快照。
  • run_manifest.json：seed、episode 数、车辆数、gamma、设备、最终 reward/queue 等运行信息。
  • plot_reward_data.txt、plot_delay_data.txt、plot_queue_data.txt：每个 episode 的指标数据。
  • plot_reward.png、plot_delay.png、plot_queue.png：如果安装了 matplotlib，会生成对应曲线图。

结论

这个代码库的主线很清楚：SUMO 提供真实交通仿真，环境把它压缩为 12 维队列状态；DQN 学习 4 个相位动作的价值； 奖励采用负的未服务队列成本；解析转移模型 f 与 DQN 尾部价值一起支撑 rollout 控制。 真正开始训练前，最关键的不是改代码，而是确认 SUMO、Python 依赖和 intersection/ 网络资产都已就位。
